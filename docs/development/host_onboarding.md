# Host Onboarding Process

This guide explains how to add new hosts to this Nix configuration system.

## Prerequisites

Before adding a new host, ensure you have:
- SSH access to the target machine
- Root access or sudo privileges
- Basic hardware information (CPU, memory, storage)
- Network configuration details
- SOPS encryption keys (for secret management)
- Git access and permissions

## Step-by-Step Process

### 1. Hardware Inventory

First, document the hardware details using the existing hardware survey script:

```bash
# Run hardware survey on the new host
scripts/hardware-survey.sh
```

This creates a `facter.json` file for the host, which can be placed in the host directory.

### 2. Create Host Directory Structure

Create the necessary directory structure for your new host:

```bash
# For a new desktop
mkdir -p hosts/personal/desktops/<hostname>

# For a new server
mkdir -p hosts/personal/servers/<hostname>
```

### 3. Generate Host Configuration Files

Create the basic host configuration files:

- `hosts/personal/desktops/<hostname>/configuration.nix`
- `hosts/personal/desktops/<hostname>/hardware-configuration.nix` (if applicable)
- `hosts/personal/desktops/<hostname>/facter.json` (if you have one from survey)

### 4. Generate SSH Management Keys

Generate management SSH keys for the host:

```bash
scripts/servers/create-management-key.sh <hostname> <profile>
```

The profile should be either "personal" or "work" depending on the host.

### 5. Add Host to Secrets Management

Create the secret directories and add host-specific keys.

Add to `flake.nix` in the `secretsByProfile` section:

```nix
<hostname> = {
  primary = <profile>DesktopRoot "<hostname>";  # or <profile>ServerRoot
  shared = sharedCommonRoot;
  profileShared = <profile>SharedRoot;
  # ... additional paths as needed
};
```

Update `.sops.yaml` with the host's Age public key.

### 6. Configure Host in Flakes

Add the host to the appropriate configuration in `flake.nix`:

```nix
nixosConfigurations."<hostname>" = nixosSystem {
  system = "x86_64-linux";
  modules = [
    # Base modules
    ./hosts/personal/desktops/<hostname>
    # ... other modules
  ];
};
```

### 7. Add to Documentation

Update the README.md with information about the new host:

```markdown
| Host | Type | Profile | Description |
|------|------|- -- ----|-- -----------|
| <hostname> | <type> | <profile> | <description> |
```

### 8. Test Configuration

Verify the new host configuration builds correctly:

```bash
# Build the configuration
nixos-rebuild build --flake .#<hostname>

# Test the configuration (dry-run)
nixos-rebuild test --flake .#<hostname>
```

## Host Template Files

### Basic Host Configuration (`configuration.nix`)

```nix
{ config, lib, pkgs, ... }:

{
  imports = [
    # Base configurations
    ./hardware-configuration.nix
    # Profile modules
    ../../modules/features/base
    # Feature modules
    ../../modules/features/desktop
    # Add other modules as needed
  ];

  # Host-specific settings
  networking.hostName = "<hostname>";

  # Hardware-specific settings
  # (These will be filled automatically by hardware-configuration.nix)

  # Enable desired features
  desktop.gnome.enable = true;
  # ... other feature enables

  # Override defaults if needed
  # lukasf.<feature>.someOption = <value>;
}
```

### Hardware Configuration Template

The hardware configuration is typically generated automatically but can be manually created:

```nix
# hardware-configuration.nix
{ config, lib, pkgs, ... }:

{
  # This file will be automatically generated by NixOS
  # but can be manually edited for specific requirements

  # Filesystem mounts
  boot.initrd.availableKernelModules = [ "nvme" "xhci_pci" "ahci" "usbhid" ];
  boot.initrd.kernelModules = [ ];
  boot.kernelModules = [ ];
  
  # Root filesystem
  boot.rootDevice = "/dev/disk/by-label/NIXOS_SD";
  
  # Network configuration
  networking.interfaces = {
    # network interfaces configuration
  };
}
```

## Host Types

### Desktop Hosts

Desktop hosts typically enable:
- Desktop environments (GNOME, Plasma, etc.)
- Gaming features
- Power management modules
- Development tools

### Server Hosts

Server hosts typically enable:
- System services
- Storage modules (Ceph, etc.)
- Network security modules
- Monitoring tools
- Automation modules

## Common Issues and Solutions

### SSH Key Issues

If SSH access fails:
1. Ensure the public key is in the correct SOPS file
2. Verify the key paths in the secrets configuration
3. Run `sops updatekeys` to update permissions

### NixOS Build Issues

If build fails:
1. Ensure module dependencies are properly specified
2. Check that all options have valid defaults
3. Review the error messages for specific failures

### Firewall Issues

For networking issues:
1. Verify network configuration in the host config
2. Check that required ports are open in the firewall module
3. Test network connectivity separately

## Testing New Host

After adding a new host:
1. Build the configuration
2. Test the configuration without applying changes
3. Perform a dry-run deploy
4. Verify service functionality
5. Confirm secrets work correctly
